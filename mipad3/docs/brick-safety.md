# Защита от кирпича (приоритет №1)

Статус знаний: (V) проверено по источникам, (U) НЕ проверено на Mi Pad 3, сверить до флешинга.

## Правила (нарушать нельзя)
1. НИКОГДА не писать в preloader / boot0 / boot1 (eMMC boot-разделы) и не трогать lk. Это цепочка MediaTek: BootROM -> preloader -> LK -> ядро. Пока preloader цел, планшет можно вернуть. (V общая схема MTK; U для этой платы)
2. Ставим только в userdata, как ios-sweet (стирает Android), а не в системные разделы. Boot-образ только временный: fastboot boot, без записи во флеш. (V подход ios-sweet; U поддержка `fastboot boot` в LK Mi Pad 3)
3. До любой записи: полный бэкап ВСЕХ разделов (особенно preloader, nvram, nvdata, proinfo, seccfg, frp, lk, boot, recovery). Бэкап хранить на ПК в двух копиях. Без бэкапа не флешим. (U: чем снимать, mtkclient или SP Flash Tool, проверить поддержку MT8176)
4. Вход в аварийный режим: у планшета работают Power и кнопки громкости (подтверждено владельцем), не работают только home/back-кнопки. Fastboot: Vol- + Power при включении, либо `adb reboot bootloader` из Android. BROM-режим mtkclient кнопками громкости тоже доступен. Проверить оба пути ДО стирания Android. (U: на самом планшете не пробовали)
5. Разблокировка загрузчика Xiaomi может требовать аккаунт Mi Unlock и ожидание. Делать позже, когда будет что ставить. (U)
6. Проверить, есть ли у Mi Pad 3 BROM-вход (BROM mode через USB), запасной путь восстановления, и нужна ли авторизация (SLA/DAA). (U)
7. Для OTA позже: схема A/B на eMMC, новый образ пишется в неактивный слот, переключение только после успешной загрузки; откат при сбое. Предзагрузочные разделы OTA не трогает.

## Порядок до первой записи
1. Выяснить, грузится ли Android, работает ли adb, на каком режиме загрузчик (`fastboot oem device-info`).
2. Снять полный бэкап, проверить контрольные суммы.
3. Проверить путь восстановления из бэкапа ДО того, как стирать что-либо.
4. Только потом: временный fastboot boot, и только потом userdata.

## Результаты поиска (2026-11-12)
- (V, источники) Бэкап: mtkclient умеет `mtk rl out` (все разделы), `mtk printgpt`, `dumppreloader`. В списке обхода авторизации SP Flash Tool есть MT8173 (XDA). MT8176 там не указан, это тот же семейный чип, но поддержка в mtkclient НЕ подтверждена: проверить на живом планшете. Infinity-Box заявляет поддержку MT8176.
- (V) У mtkclient два режима: BROM (зажать кнопки громкости при подключении USB) и Preloader (кнопки не нажимать, просто подключить USB). Кнопки громкости у планшета работают, так что оба режима доступны (U: MT8176 в mtkclient не подтверждён).
- (V, форумы) Fastboot на Mi Pad 3: Vol- + Power; recovery: Vol+ + Power. Обе комбинации доступны, кнопки громкости работают. Запасной вход: `adb reboot bootloader` из работающего Android.
- (V, форумы) На Mi Pad 3 работают `fastboot flash recovery` и `fastboot -w`. Именно `fastboot boot` для этого планшета подтверждения не нашёл (U).
- (Анекдот, U) Один владелец писал, что его Mi Pad 3 пришёл с уже разблокированным загрузчиком. Проверять только `fastboot oem device-info` на твоём.
- (U) Ожидание Mi Unlock: источники расходятся (72 ч для моделей до 2018 в одной вики). Для Mi Pad 3 точно не подтверждено. Приложение может не видеть планшет в fastboot без правильных драйверов.

## Первый запуск M1 через `fastboot boot` (2026-11-13)
- Образ ничего не пишет в флеш: только читает ID-регистры, трогает GICv2 (0x10221000/0x10222000), таймер, UART0 (0x11002000) и framebuffer из /chosen/atag,videolfb.
- Защита: адрес framebuffer принимается только внутри DRAM (0x40000000..0x140000000, выровнен на 4 КБ), иначе вывод только в UART.
- Выход после теста: через 30 с образ делает PSCI SYSTEM_RESET (smc), планшет перезагружается в Android. Запасной выход: долгое удержание Power (кнопка Power работает, подтверждено владельцем).
- Если LK заблокирован, `fastboot boot` просто откажет: это безопасный исход.
- Риск (U): обращение к UART0 или GIC при выключенных тактах может подвесить шину. LK обычно держит UART включённым.
- Порядок: `adb reboot bootloader` -> `fastboot oem device-info` -> `fastboot boot m1-boot.img`. Если gzip-образ не принят, пробовать `m1-boot-raw.img`.
